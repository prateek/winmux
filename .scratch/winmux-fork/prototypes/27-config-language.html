Config language bake-off

Throwaway prototype for Prototype: config and scripting language (ticket 27). One reference config, written seven ways. Pick a tab, choose which candidates to compare, and read across.

  • What's real and what isn't. Your live ~/.config/winmux/winmux.toml has gaps, the sidebar and key bindings, but no Lenses, Columns or window rules yet. Those parts are representative, built from the decided shapes: the three default Lenses (Lens configuration shape), the place/move-boundary hooks and precedence chain (fixed Columns grilling), and your own Mail→Comms routing rule from codex-columns.
  • Candidates. (A) TOML + CEL, today's decision. (B) Janet for everything, no TOML: the Lisp pick, with Fennel and s7 covered in notes. (C) TOML for static settings plus JS hook functions on JavaScriptCore. (D) HCL, Terraform's language: blocks plus a real expression grammar. (E) Nickel: JSON-shaped, with functions, gradual types, contracts and merge priorities. (F) Dhall: typed, total, no Turing-completeness. (G) Guile Scheme in the style of Guix's configuration records.
  • Verified facts. Licences from each repo: Janet MIT, Fennel MIT, Lua MIT, cel-js MIT, s7 0BSD. Janet 1.42.1's janet.c is 3.4 MB / 58.7k lines, compiles with clang -O2 in 2.7 s to a 1.15 MB object, and ran a place hook from C on this Mac. The Janet parse error on the Errors tab is real output. No Swift HCL parser exists; hcl-rs is MIT/Apache-2.0 with expression evaluation, Go hashicorp/hcl is MPL-2.0, Nickel is MIT and its 1.18 release ships a C API with a 13.3 MB arm64 dylib; the Nickel errors on the Errors tab are real output from its CLI here. Dhall's reference implementation is Haskell (BSD-3), and its own docs confirm it can't compare Text. Guile 3.0.11 is LGPL-3.0+; Guix doesn't run on macOS. Unverified: that janet.c drops into SwiftPM as a C target without patches, cel-js's bundle size, whether cel-js ships CEL's cel.bind macro.
