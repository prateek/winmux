# Handoff: building the WinMux fork foundation

The fork foundation is built on top of upstream `v0.5.6`: the deployment target, Nickel config, dogfood release, Filter contract, Global MRU, config hot reload, Lenses, thumbnail cache, miniatures, Accessory defaults, shared Tiles, strip and cmd-tab ownership, fixed Columns and Column Policy hooks are implemented. The shipped defaults now provide all six Lenses, their Triggers and the `window` binding mode, with Columns off; subscriptions include config, Lens and Column events. `0.5.6-dogfood.1` is published. Every child of the foundation umbrella issue is built; the installed/release and physical-device checks below remain Prateek's. Releases now follow every land to `fork`. Last updated 2026-10-15.

## How to read an issue

- **Decisions** are settled. Don't reopen them; if the code makes one impossible, stop and tell Prateek.
- **Defaults chosen for you** are starting points no ticket settled. Change one if the code argues for it, and say so in the pull request.
- **Open details** remain in one issue only, the strip. Both can only be answered by running a build.
- When an issue and a ticket disagree, the issue is right. The issues apply later amendments.
- If an issue body needs correcting, edit the draft in `.scratch/winmux-fork/build/` and update the issue from it, so the two stay the same. The drafts use `{{UMBRELLA}}` and `{{CHILDREN}}` placeholders for the issue numbers.
- **How far to trust the issues.** They were drafted by agents from the tickets, reviewed once against the tickets and the code, then patched. The review's three errors and the gaps it found were fixed, and the issues were checked against each other for names, key defaults and import paths. Nobody has re-read all twelve end to end since the patch. Treat a claim about existing code (a file path, a function name, a current default) as probably right, and check it before building on it.

## Lens implementation for the next builder

- `Sources/AppBundle/lens/` owns candidate collection, sort, Search, session state, lifecycle and inline evaluation. `SwitcherPalette` is the list panel and reads that state. Extend the Presentation there rather than making another eligible-window pipeline.
- AX candidate record reads overlap, preserve candidate order and omit failed/gone windows. The Filter context reuses those records and tolerates failed extra record reads. Opening tickets are cleared on throwing exits without cancelling a newer open.
- Candidates combine workspace windows and the global minimized container, plus opted-in popup classes. Explicit `--all` must not discard a minimized window with no known origin. Popup classes now follow live activation policy; bundle identity controls the floating default for newly registered windows.
- `LensConfig` resolves the implicit `default` profile and merges custom keys over defaults. A session snapshots entries, names, settings and key commands; reloading config does not replace them. Filter functions remain in the helper.
- Search uses user-facing workspace and project names, while Filter records retain their existing ids. Its matcher is shared by the list and scripts. Each word chooses the highest tier times field weight, with title/app winning weighted ties. JSON uses `score` and `matched-field` (comma-separated when words match several fields).
- `LensSearchMatch` carries title/app character-offset ranges in the original displayed strings, including lowercase expansions. The session caches applied Search results; inline Search uses unhighlighted snapshots. Explicit Search applies to strips immediately; a remembered Search never filters a strip at opening, whatever its `starts-in`, and waits for the list. Picture Tiles retain no title bar and highlight their selection footer; empty titles use app ranges.
- `TileWindowControls.swift` shares fitted-picture and control geometry between drawing and hits. `LensTileHit` carries index, window id and an optional control from one results snapshot. The prototype's circles scale with layout and selection, shrink uniformly only to an actual ten-point diameter, and disappear below it. `LensSession.hoveredTileId` is independent of selection and appears in the opening trace's session text/JSON. One motion decision feeds both hover and selection; outside-frame moves clear hover. Controls re-anchor and clear hover before dispatch, so a stationary pointer cannot close the next Tile.
- `Window.windowRecordWithAttributes` returns the Filter record and its AX attributes from one read. Lens button flags stay beside the record through `LensWindow` and `TileEntry`; the Filter schema is unchanged. `WindowAxRecordAttributes.read(from:buttons:)` reads whether each button is there and enabled only when a Lens asks (`windowRecordWithAttributes(buttons: true)`); the green control needs `Ax.fullscreenButtonAttr`, or `Ax.zoomButtonAttr` with the `AXFullScreenButton` subrole. `TileControlAvailability(buttons:windowClass:)` hides minimize on minimized, fullscreen and hidden-app windows, and fullscreen on hidden-app windows. `runLensWindowAction` is shared by keys and explicit-id controls, including restoration before minimize/fullscreen. Controls bypass marks and never dismiss; a control that succeeds reads the window again and refreshes its Tile through `LensSession.refreshTile`. The hosting view accepts first mouse, because native fullscreen can make the open Lens non-key and otherwise consume the next control click.
- `LensLifecycle` owns closed, opening (gesture, snapshotted keys, queued key meanings, release and a prepared staying session), committing-ready and presented state. Search, selection, modifiers, Presentation and dismissal are explicit events; the panel only shows/hides and routes AppKit input. The owner cancels every effect on dismissal/replacement. An async closure formed in a generic function, a function with a `some` parameter, a protocol extension or a method of a generic type, and then stored or returned, names its isolation (`@MainActor`, another global actor or `@concurrent`): the release's compiler loses the return to the caller's actor otherwise, and only in an optimised build. `LensInlineSearch` implements its 150 ms debounce and 50 ms display deadline with an injected `any Clock<Duration>`; late replies and cleanup check request identity. - Lens Focus restores minimized windows to their retained origin, recreating the workspace if cleanup removed it; unknown origins use the current workspace. Workspace commands restore before moving; Close does not restore. Popup Focus raises it natively; popup Summon and workspace moves fail without moving it into a tiling tree.
- `restoreLensWindow` and `SummonCommand` restore minimized/hidden windows before acting. Summon runs `ColumnPolicy.place` once for each incoming tiling window on a Columns destination. Floating windows remain floating; windows already on the destination are only focused. Ordinary destinations preserve their previous behavior. Its restoration suppresses Place until Summon has restored the native window. It never runs Arrive.

## Columns implementation for the next builder

- `Workspace.columns: ColumnState?` is the enable gate. `ColumnState` in `tree/Columns.swift` holds the configured `count`, physical `slotCount`, declared/current fractional widths, focus tracking and the previous root. Only squeeze extends physical slots, by one. Emptying that extra slot removes it and restores declared widths. Reload replaces Column state and runtime count overrides. Turning Columns off clears root slots.
- `enforceColumnInvariant` runs after flatten normalization and before optimistic layout. It forces horizontal tiles, recovers a wrapped root, keeps valid unique slots and folds extras. The fast path updates weights and sorts children without binding or MRU propagation. Recovery restores MRU; normalization exempts Column nodes while still running inside them.
- `tree/ColumnPolicy.swift` owns hook arguments, validated placement decisions, mutation and post-placement commands. `decision` excludes the arriving window from helper records and chooses a target and typed `OverflowPolicy` without binding or running commands. The pure `tree/ColumnPlacement.swift` resolver interprets occupancy and Overflow and returns a slot, effect, widths and landing region. `bindToColumn` resolves current state and applies that answer; `place` still normalizes before `run`. Arrive captures the detected workspace's Columns and binding-default Window class before placement, routes first, honors the Accessory floating default/override, and either supplies an explicit Column or falls through to destination Place. Place's commands precede Arrive's commands. Nested Run lists are suppressed and logged once per outer list, while their placements still happen. Popups also receive Arrive; placement fields are always ignored while they are popups, but Run executes. Promotion runs Arrive again with the real class before Place. Hook record reads overlap; actions recheck binding revisions and destination state after awaits. Closing or moving a window abandons a pending action without a dialog; an abandoned destination Place also stops Arrive's pending Run list. A failed hook records a unified-log error and `config status` last-error; built-in placement still binds the window.
- New-window registration temporarily holds the window outside the tiling tree so Arrive decides its first tiling placement. Cache restoration skips Arrive and uses Place for restored tiling windows only when Columns are on and a Place hook exists. Classification does not construct disposable Column bindings. `WindowRelayout`, native-state restoration, workspace/monitor/project moves, cross-workspace, cross-Column or floating-to-tiling drops and floating shake restoration route through Place. Group drops place each arriving window. Floating shake placement finishes before the async mouse-up drag pass. Closing and movement inside a Column invoke neither hook.
- `Command.run` owns policy for movement commands, so direct callers and `stack-with` use it too. With no hooks, Move follows the Fixed Columns implementation. Every Place and Move-boundary eligibility check uses `ColumnPolicy.hook`, whose gate is destination `Workspace.columns`. `MoveCommand` asks Move-boundary only for an occupied horizontal neighbour or the workspace edge. Join uses explicit Overflow policy or Place's Overflow policy; swap exchanges whole Columns. Empty neighbours bypass the hook. No-hook workspace edges retain `--boundaries` / `--boundaries-action`, and monitor transfers still apply destination Place.
- `SummonCommand` restores native state with `runPlace: false`, then calls Place exactly once per incoming tiling window on a Columns destination; floating windows remain floating and current-workspace windows are only focused. Summon never calls Arrive. `LensLifecycle.updateMiniatureLanding` obtains the same validated decision as `place --dry-run`, then shares `ColumnPlacement.resolve` with binding. `miniatureColumnLanding` turns its region into a frame; the Lens interprets no Overflow strings or squeeze widths. Floating and current-workspace branches stay local. Published landing geometry redraws both Presentations. Selection cancellation, the once-per-destination helper-record cache and selected-window exclusion remain; publishing checks selection, destination and Column-state identity.
- `command/impl/ColumnCommands.swift` implements focus, explicit movement, widths, compact, listing, runtime count and dry run. `focus-column` sets `focusedSlot` even when empty; `FocusedEmptyColumnPanel` follows it. Width commands use `ColumnState.setWidth`/`stepWidth` and `config.columns.widthPresets`, including in vertical splits. `move-node-to-column` joins an occupied target's tab group. Compact packs toward Column 1 without carrying widths along. Dry run targets the focused destination workspace, prints the built-in decision and hook failure and returns 0 for a failed hook, and never executes `run`.
- Root `layoutTiles` uses current fractions and physical slot positions, including reserved empty gaps and squeeze. Width editing, divider previews and window-edge dragging share the 80-point minimum and proportional proposal. `balance-sizes` restores declared widths, retaining a populated squeeze slot. Dividers are omitted while floating/fullscreen windows are present. `resize width` inside a split with no horizontal split remains an error; `column-width` is the direct Column operation.
- `columns-changed` runs at the end of `refreshModel`, after normalization. `ColumnsEventTracker` refreshes snapshots for every workspace by name, emits only a changed focused workspace, silently baselines every workspace on the first refresh after launch, compares a workspace created later against its own Columns with nothing in them, and drops removed workspaces. Focus-following transfers and new windows taking focus compare with the destination's prior baseline. Existing roots and recursive occupancy checks avoid creating roots or leaf arrays. Turning Columns off emits empty state; divider commits emit once.
- `FixedColumnsTest` retains the no-hook expectations. `ColumnPolicyTest`, `ColumnCommandsTest`, `ColumnsConfigTest` and real-helper tests cover contracts, smoke contexts, precedence, Overflow policies, routing, restoration, movement, previews' read-only decision, targeted commands and failure paths. Supervisor timeout/kill tests use its stub helper. Do not call `reloadConfig`/`applyConfig` in tests: they touch the real home directory. `docs/columns.md` has helper-checked Nickel examples and the command reference. CLI help remains manually maintained in `cmdHelpGenerated.swift` and `subcommandDescriptionsGenerated.swift`.
- Fixes made after the last live run, covered by tests or by reading only: the `run` recursion guard is `ColumnPolicy.runningWindows`, keyed by window id, because an unstructured `Task` inherits task-locals; the fall-through Place hook always sees `class = 'tiled` (also checked live in the shared-placement build); an abandoned Place inside Arrive or `relayoutWindow` falls back to the built-in binding while the window is still where it was; an abandoned boundary move returns failure; the landing spot is not recomputed for an unchanged selection (also checked live with the policy-timing count); `stop()` cancels a pending shake placement; a popup is announced with `window-detected` at promotion, not at registration. Known limits: a hook call cancelled with its refresh session (a hotkey pressed while Arrive gathers its arguments) falls back to the built-in placement and Arrive is not retried; a promoted popup has had Arrive's `run` list twice, once as a popup; `on-window-detected` in a TOML config reports both the removal message and "Unknown top-level key".

## Default config and events implementation

- `nickel-helper/nickel/winmux/defaults.ncl` is the source; `make default-config` regenerates the static JSON. The upstream fixture is `nickel-helper/tests/fixtures/upstream-default-config.toml`. Conversion replaces default modes with the TOML's modes when present, adds only unbound `alt-slash` and `alt-shift-o` using Swift-compatible modifier/preset/alias identities, adds the `window` mode with its `alt-semicolon` Trigger only when the TOML has neither a `window` mode nor an `alt-semicolon` binding in `main`, and keeps all six Lenses. Omitted upstream bindings stay absent. Without TOML modes it imports defaults whole. Converted comments explain removal. Duplicate user chords and a `mode` table without `main` fail conversion. The converted file removes `mode` from the imported defaults and merges the converted modes at normal priority, so later merges over it still apply. The converter's Dvorak and Colemak tables are a copy of `KeyboardLayoutMaps.swift` with no parity test: change both together.
- `config-version` is accepted and ignored by `W.Config`, dropped before the Swift bridge like `contract-version`, and absent from defaults and new conversion output. TOML at version 1 or lower, or unversioned, with no explicit persistence list is converted with the previously inferred workspace targets and force-assignment keys in source order, plus a warning; nothing is written when nothing is inferred. Commands are split as `splitArgs` splits them, so a quoted name is one target. Nickel persistence is explicit.
- **Leaving the windowing mode:** the default `window` binding mode has 44 keys; `w`, `o`, `f`, `s`, `r`, `a` run `mode main` before their Lens command. `r` and `a` explicitly use `--presentation list --tile text`; Escape and Option-semicolon return to main. All other keys keep it on, even if their command fails. Main chords are inactive and unbound keys reach the app. A bottom-centre non-activating HUD names every enabled non-main binding mode, follows monitor focus through layout refresh and hides synchronously on mode changes before Lens opening. `BindingModeHud` shows, moves or hides its panel only when the text or the monitor's frame changed, and reads the focused monitor only while a mode is shown, so the startup `activateMode` touches no focus state and a Lens opened in a sticky mode stays above the HUD. Reloads keep or drop it with `Config.modeToKeep`; disable clears it. Carbon callbacks resolve the current mode's binding rather than retaining the first registered command for a shared chord. Lens commands alone do not change user modes. The old default `lens` mode is removed without an alias; merges can still define a user `lens` mode, while reads of `defaults.mode.lens.binding` get a rename hint. Earlier converted files retain their own old mode and Trigger. The rename hint is given only when the record missing `lens` has `main` and `window` fields. `list-lenses --json` lists settings rather than Triggers; tests read bindings.
- `ServerEvent` encodes reload-error and ad-hoc-name nulls explicitly; old event omissions stay unchanged. The existing reload `defer` calls `configReloadEvent(dryRun:error:configPath:)`, a pure function tested for success, diagnostic failure and dry run. Superseded loads return before that defer and emit nothing.
- `LensLifecycle` emits on entering/leaving presented, after the panel is ordered front. Committing-ready is silent. Quick committing taps inside the display delay emit neither; staying Lenses are presented immediately. Search, handoff and Presentation conversion keep one pair. Ad-hoc sessions retain the Filter name/body.
- Column snapshots use workspace names, replacing `ObjectIdentifier` and its freed-object alias risk. Baselines cover all workspaces on each refresh; the first refresh after launch and unchanged focus switches are silent. Columns off emits zero/empty arrays and divider commits emit once.
- `docs/default-config.md` and `docs/events.md` document imports, removal, Triggers, the binding mode and exact payloads. Their Nickel examples and the existing Lens/Column examples pass the real helper. CLI help is still manually maintained.
- Live driver notes: sample configs outside the XDG parent prevent a relative `winmux/winmux.ncl` import from resolving to the active config instead of the shipped library. Put extra capture bindings inside a `binding | force` replacement record; adding a sibling nested binding is discarded by that force priority. The Accessory evidence app can remain unregistered and visible across WinMux workspaces; do not assume it has a managed window id.
