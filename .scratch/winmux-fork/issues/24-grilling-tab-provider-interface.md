# Grilling: tab provider interface

Type: grilling
Status: resolved

## Question

Instead of per-app code, apps plug their tabs into WinMux through registered tab providers, matched by bundle id (see §10 of [the tab research](../research/18-reading-app-tabs.md)). Decide the interface:

- **Modes:** pull (a command WinMux runs when a Lens opens, with a timeout, printing JSON, like Alfred's Script Filter), push (a long-lived watch command such as `cmux events`, or a `winmux tabs publish --app-id --pid` verb an app or extension calls itself), or both.
- **Schema:** one versioned document per app. Window match hints in priority order (exact `CGWindowID`, then pid plus title, pid plus bounds, pid alone), and per-tab `id`, `title`, `url`, `path`, `group` (a sidebar item such as an Orca worktree) and a free-form `meta` map. Where an optional `jq` transform lives in the config.
- **Switching:** how a provider declares the command that brings a tab to the front (Orca's `orca terminal switch --terminal <handle>`, cmux's `focus-pane`, Chrome's `active tab index`).
- **Filter side:** the Nickel contract fields this adds (`w.tabs` as `Array Tab`, `w.document`, `w.incognito`) and how `meta` is typed.
- **Built-ins:** the Chrome-family AppleScript route and native macOS tab grouping become the first built-in providers; Orca and cmux become config entries.

Check the schema against Orca, cmux and Chrome before fixing it; freezing it too early is the main risk. The CLI verbs also feed [Grilling: CLI surface for the fork's features](20-grilling-cli-surface.md).

Starting points from §9 and §10 of the research: `w.tabsSource` (which provider answered) and `w.tabsAge` (a duration, so a binding can ignore stale tabs); absent `url` or `path` as `""` rather than optionals, so `w.tabs.exists(...)` needs no guards; `Tab.group` for the sidebar level and `Tab.meta` as `map<string, string>`. Runtime rules to confirm: pull providers run off the main thread with a hard timeout, at most one in flight per app, only when a binding references `w.tabs` (type-to-search over tab titles counts); keep the last good answer on failure, retry at most once per Lens open; restart watch providers with backoff; run `activate` only after WinMux has focused the window.

## Answer

> Amended (2026-09-30): [Grilling: the Filter contract's final field list](33-grilling-filter-contract-field-list.md) leaves `w.tabs`, `w.tabsSource`, `w.tabsAge` and `w.private` out of contract version 1, because tabs are deferred. `w.document` stays.

Resolved 2026-09-30 with Prateek. `CONTEXT.md` gains **Tab** and **Tab provider**. Written after Nickel replaced TOML and CEL, so the research's `jq` transforms and `{tab.id}` string templates are gone.

- **What a Tab is.** A Tab is something inside a window that can be switched to but isn't a window of its own: a browser tab, an editor file, a terminal in a sidebar app. Native `NSWindow` tabs are windows, so they are *not* Tabs and not a provider; they stay with [Grilling: grouping native macOS tabs in Lenses](22-grilling-native-tab-grouping.md). "Tab group" stays reserved for the Column tab group.
- **Modes: pull and set.** A pull provider has a `list` argv that WinMux runs when a Lens opens. Any process can also push its Tabs with `winmux set-tabs --app-id <id> --pid <pid>`, reading a document on stdin. A supervised `watch` stream (cmux's `events`) isn't built. A watcher is a user script piping into `set-tabs`, and a supervised `watch` goes to fog unless cmux becomes a daily app.
- **`set-tabs` semantics.** Each call replaces that pid's whole document (no merging), and the document is dropped when the process exits. When one app has both a pull answer and a pushed one, the newer wins. No config entry is needed to push, so a VS Code extension works with no setup.
- **Provider record, in Nickel.** Fields: `name`, `app-ids` (a list, so one Chrome-family entry covers derivatives), `list` (argv, pull only), `transform` (a Nickel function from the app's parsed JSON to the schema, optional), `focus` (a Nickel function from a Tab to an argv, never a shell string), `ttl` (default 2 s) and `timeout` (default 300 ms). A config entry with the same app-id overrides a built-in.
- **Schema.** One document per app process, `version = 1`, marked experimental until Chrome, Orca and cmux all fit it. Each window record has a `match` (`windowId` exact, then pid plus title, then pid plus bounds, then pid alone when the app has one window), an optional `private : Bool`, and a flat `tabs` list. A Tab is `{ id, title, url, path, group : String, active : Bool, index : Number, meta : { _ : String }, focus : Array String (optional) }`. A Tab is whatever `focus` can target: for Orca, one terminal leaf titled by its terminal, with the worktree as `group`. Deeper levels (Orca's tab and split leaf, cmux's pane and surface) go in `meta`. Checked live against Orca's `terminal list --json` on 2026-09-30; cmux only against `--help`, since its socket wasn't running.
- **Filter contract.** `w.tabs : Array Tab` (without `focus`), `w.tabsSource : String` (the provider's `name`, or `""`), `w.tabsAge : Number` (seconds since the last good answer; Nickel has no duration type), `w.document : String` (read from `AXDocument` by WinMux, no provider), and `w.private : Bool`. A missing `url` or `path` is `""`. Search doesn't match Tabs of private windows.
- **When pull providers run.** No reference gating: Search matches tab titles in every Lens with a Search box, and spotting references inside Nickel functions is hard. On every Lens open, WinMux refreshes each provider whose app has a window among the Lens's matches, unless its last answer is younger than `ttl`. Runs happen off the main thread with the hard `timeout` and at most one in flight per app. A failed run keeps the last good answer and is retried at most once per Lens open.
- **Switching to a Tab.** WinMux uses the Tab's own `focus` argv, then the provider's `focus` function, then the built-in route. A Tab with none of these just focuses its window. The order: focus the window through `nativeFocus`, wait for OS-confirmed focus (the `lastFocusedSeq` write), then run the argv with a 1 s timeout. On failure the window stays focused, and the error goes to the log and `list-tab-providers` with no notification. Pushed argvs run only when you pick that Tab, and any local process could run commands anyway, so they aren't sandboxed.
- **Built-ins and shipped config.** Chrome-family AppleScript is the only built-in, running in-process ([Prototype: Chrome-family AppleScript tab source](23-prototype-chrome-tab-source.md) builds it against this shape). The default config ships an Orca entry (`list = ["orca", "terminal", "list", "--json"]`, `focus` running `orca terminal switch --terminal <handle>`), which stays inert without Orca. cmux gets a docs example only.
- **CLI** (feeds [Grilling: CLI surface for the fork's features](20-grilling-cli-surface.md)), named after the existing flat verb-noun commands: `list-tabs [--window-id N] [--refresh] [--json]` reads the cache (refreshing first with `--refresh`); `set-tabs --app-id --pid` pushes; `focus-tab --window-id N --tab-id ID` focuses the window and then switches; `list-tab-providers [--json]` shows each provider's name, apps, last run, age and last error. The research's `tabs publish`, `tabs activate` and `activate` field are renamed accordingly.
