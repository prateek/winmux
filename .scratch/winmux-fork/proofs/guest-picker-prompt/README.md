# Guest private-picker probes

Run only in the issue's authorized guest, through the VM skill. `watch.swift` polls visible CoreGraphics windows every three seconds, logs every owner outside desktop furniture with UTC time and the explicit capture-loop count, and screenshots each changed set. It also logs the staged apps and WinMux panels; their presence alone is not a permission prompt. Its screenshots are additional captures outside the numbered loop; each poll also reads replayd’s total use count from the plist. The initial watcher had a layer filter that missed the prompt. The corrected watcher was validated against the unanswered dialog: UserNotificationCenter at layer 8.

`reproduce.sh` runs 270 stills and 30 one-second system videos, then the demo skill's `trace-recorder`. Compile that recorder with `swiftc -O trace-recorder.swift -o trace-recorder`. Compile `watch.swift` with `swiftc -O`. The initial repro was extended with another 630 stills and 70 videos. `lenses.sh` is the initial Escape-key probe; it did not close the CLI-opened strip and is retained only to explain that evidence. `lenses-v2.sh` verifies `active=true` after opening and `active=false` after toggling the same named Lens closed, once per minute. Give it an output directory and a minute count (120 for acceptance).

`alter-approval.py` and `control.sh` change one field in the observed ssh-wrapper approval. Stop other capture producers first. The control terminates replayd before writing, then saves the plist before/after one two-second video and a final still. A prompt stays unanswered; clear it with the authorized VM stop/up cycle, restoring the saved approval before boot. The first controls wrote before terminating replayd and were invalidated by its cached writeback; keep them apart from the corrected controls.

`accept-captures.sh` preserves 900 stills and 100 one-second videos, with every successful command numbered. Run it beside `lenses-v2.sh` and the watcher in a fresh clone of the rebuilt image. After both complete, stop/up the guest, restart the watcher and record a short system video and a trace-recorder take. Move the approvals file aside for the preflight failure proof, restore it, and require `ok approvals` again. Save readbacks and screenshots before closing the staged apps.

`accept-start.sh` verifies the four standing-desk windows on both workspaces, closes only blank Safari windows left by switching from the rich set, restarts WinMux with both XDG directories under `~/demo`, and starts both loops beside a new watcher and filtered log stream. It expects the preparation watcher PID in `~/takes/fresh/watch.pid`; create that watcher before staging the desks. It preserves the process ID and requires it to remain unchanged through the timer. `status.py` summarizes the saved logs and process identity without sending input to WinMux. A healthy checkpoint has no unexpected owner or alert/hint request and a recent watcher sample. The first and last timed openings have screenshots as well as traces.

After the capture loop prints `DONE`, `audit-media.py` checks all 900 PNG headers/dimensions and uses ffprobe to require a positive-duration 1280×720 video stream with packets in every movie. On the host, `monitor.py <vm-path> <guest> <checkpoint-jsonl>` records a checkpoint every 50 seconds through `vm ssh`, stopping for an unexpected owner, alert/hint, changed process or stalled run. It exits successfully only after both loops report `DONE`; it never stops or restarts the app.

`after-run.sh` refuses to run until both loops have finished. It saves WinMux's final trace/focus/workspace/windows, then stops the debug build and uses `close-owned.swift` to close only the four desk apps' AX close buttons before process cleanup. Run it only after the complete timer. Reboot with the VM skill's stop/up cycle in a persistent host shell. `post-reboot.sh` watches and records both three-second takes with media metadata; inspect the metadata and final screenshots. `missing-approval.sh` moves the plist aside under a restoration trap, requires preflight exit 1 and its approvals failure, restores it and requires success. All these guest commands run through `vm ssh`.

`date-fault.sh` is a separate positive control, run after acceptance on a clean desktop. It ages only last-use by 31 days, requires preflight's stale-date failure, starts the corrected watcher before capture 1 and requires mechanical detection of UserNotificationCenter. Leave the dialog unanswered, clear it with the authorized stop/up cycle and verify renewal and recording again. Keep this expected-prompt phase separate from the no-prompt acceptance logs.
